Your cluster ships a full observability stack **already running** — part of the pre-built platform, like the cluster and the gateway. It's for *you*, the operator: dashboards over the cluster and your agent fleet, no setup required.

## What you get

Provided by OpenShift operators across several namespaces:

- **Grafana** — dashboards (login `admin` / `openclaw`), available at **`/grafana`** on the workshop site or via its OpenShift Route (in the `monitoring` namespace).
- **Prometheus (via Thanos Querier)** — metrics from the OpenShift Cluster Monitoring Operator (`openshift-monitoring` namespace).
- **Alertmanager** — alert routing, also from the Cluster Monitoring Operator (`openshift-monitoring` namespace).
- **Loki** — log aggregation via the Loki Operator (`openshift-logging` namespace).
- **Tempo** — distributed tracing via the Tempo Operator (`observability-hub` namespace).
- **OTEL Collector** — trace ingestion endpoint (`observability-hub` namespace).

The **OpenShift Cluster Monitoring Operator** provides Prometheus (exposed through Thanos Querier) and Alertmanager; the **Loki Operator** provides log aggregation; the **Tempo Operator** provides distributed tracing; and the **OTEL Collector** handles trace ingestion. A standalone **Grafana** in the `monitoring` namespace has all datasources pre-wired. A custom **Agent Fleet** dashboard tracks your sandbox pods' CPU, memory, and restarts.

## Open it

The stack is up across several namespaces — confirm the pods are running:

```bash
oc -n openshift-monitoring get pods
oc -n openshift-logging get pods
oc -n observability-hub get pods
oc -n monitoring get pods
```

<ServiceLink service="grafana">Open Grafana</ServiceLink> and log in as `admin` / `openclaw`. You'll land on the pre-loaded **OpenShell Agent Fleet** dashboard (CPU / memory / restarts per sandbox); the built-in Kubernetes dashboards are there too. (It's served right here at **`/grafana`** on the workshop site — a same-origin proxy to Grafana's in-cluster Service.)

<Callout type="note" title="Pre-deployed (and how to skip it)">
The operator-managed components (Prometheus, Loki, Tempo, OTEL Collector) provision with the platform. The standalone Grafana is deployed by the Helm chart and can be opted out by setting <code>DEPLOY_MONITORING=false</code>.
</Callout>

## Watch the fleet

Open the **OpenShell Agent Fleet** dashboard in Grafana. As you create more sandboxes (Part VI's multi-agent app), each shows up here — CPU, memory, restarts per agent pod — plus the gateway's own health. This is your operator view of the whole agent fleet on one screen.

<Callout type="note" title="Why the agents can't read Prometheus themselves">
Prometheus lives <em>in-cluster</em> (a ClusterIP Service). A gateway sandbox is network-sealed and only egresses to the <strong>external</strong> hosts its policy allows — it can't reach in-cluster services (that's the same isolation that keeps it off the Kubernetes API). Observability here is for <em>you</em>; if you want an agent to reason over metrics, expose a metrics API <em>externally</em> and allow that host in its policy.
</Callout>
