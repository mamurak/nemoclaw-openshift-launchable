## The toolbar (top-right of every page)

Three live tools sit in the header:

- **Live** → [Live OpenShell](/learn/live). Reads your gateway straight from the cluster: gateway health + version, the **sandbox fleet**, the **inference route** (active provider + model, key names only), and — click any sandbox — its **Logs / audit**, **Policy decisions** (every egress attempt the policy *allowed* or *denied*, color-coded with the host, binary, rule, engine, and denial reason), and effective **Policy** (full YAML). Auto-refreshes; served read-only via `/api/openshell`.
- **Approvals** → [/approvals](/approvals). Two human-in-the-loop inboxes, with a live pending-count badge:
  - **Access requests** — when the agent is denied reaching an API/website, the gateway proposes an allow-rule; **Approve** merges it into the agent's *live* egress policy, **Deny** rejects it (the gateway draft-policy RPCs).
  - **Device approvals** — browsers/CLIs asking to pair with the agent's Control UI; approve or deny each.
- **Links** — opens your cluster services in a new tab:
  - **OpenClaw UI** — your agent's Control UI (chat + device pairing), at its OpenShift Route.
  - **Grafana** — the observability dashboards (same-origin `/grafana`).
  - **OpenShift console** — the cluster web console, at its Route URL.

## The stack
- **Red Hat OpenShift** — docs.openshift.com
- **OpenShell** — the agent sandbox runtime & control plane
- **OpenClaw** — the agent & its control UI; `openclaw --help`, docs.openclaw.ai

## Concepts worth a read
- OpenShift RBAC, Security Context Constraints, NetworkPolicy.
- The agent-sandbox CRD (`sandboxes.agents.x-k8s.io`).
- OpenClaw skills, tools, device pairing, and the workspace-as-memory pattern (IDENTITY/SOUL).
- Model Context Protocol (MCP) for typed agent tools.
- Threat modeling for autonomous agents: prompt injection, credential exposure, egress control, human approval, audit logs.
- Production hardening: OIDC, per-team RBAC, external secret management, GitOps, SIEM export, supported OpenShift.
