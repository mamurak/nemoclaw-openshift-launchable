The workshop stack is a stack of stacks. From the bottom up, each layer hands a safer, more-managed surface to the one above — until at the top you have an AI agent that can only do what your policy allows.

<StackDiagram />

## Reading the stack

1. **OpenShift** — Red Hat's enterprise Kubernetes. Real OpenShift APIs + `oc`, Routes, SecurityContextConstraints, and the web console.
2. **OpenShell** (NVIDIA) — the sandbox control plane; gateway-created agents become isolated, policy-bound pods. Reached via an OpenShift Route or the in-cluster Service.
3. **OpenClaw** — the agent ("Shifty 🦞") *you create* on the gateway, running in a sealed sandbox with a web control UI.
4. **Remote inference** — the agent calls an OpenAI-compatible model endpoint for its thinking.

<Callout type="note" title="Pre-built vs. hands-on">
Layers 1–2 (the cluster and the OpenShell gateway) are <strong>pre-provisioned</strong> — Part II shows how, and Part III has you drive it. Layer 3, the <strong>agent itself</strong>, is what <em>you</em> build by hand in Part IV.
</Callout>

<Callout type="rh" title="Why a real cluster?">
Running the agent <em>on OpenShift</em> means it inherits enterprise guardrails for free: namespaces, RBAC, security context constraints, network policy, resource limits. The agent lives in a box you control.
</Callout>

## Two "gateways" (don't mix them up)
- **OpenShell gateway** (:8080) — the *sandbox control plane* (platform).
- **OpenClaw gateway** (:30789) — the agent's own *control UI*, running inside the sandbox.
